## What is worldbench

worldbench is a benchmark for **3D world generation**: one natural-language
prompt, many models, and one self-contained Three.js file from each. Every
world is run in a real browser and graded against a fixed rubric of about
two hundred items by a panel of AI judges: an **LLM** reads the source
code, a **VLM** looks at the running world, **agents** frame each biome and
re-check disputed evidence, and **deterministic metrics** measure what the
pixels actually do. Scores are out of 280 and absolute, so every model on
the [leaderboard](/leaderboard) is measured against the description, not
against each other.

The worlds are still here to explore. A score tells you how much of the
description a model built; walking around the island shows you what it
feels like.

## What it actually tests

Every model gets the same prompt and has to produce a single self-contained
Three.js scene (a floating, multi-biome voxel island) from a text
description alone, with no image, no schema, no reference file. Getting
that right takes more than scene styling. It forces the model to reason
about several different things at once:

- **Spatial / relational placement**: the prompt encodes a placement graph,
  not a list. Snow mountains sit behind the snowy conifer forest, which sits
  beside the highlands, which slope down into a flowering grove; desert and
  volcano have to stay physically and hydrologically separate. The model has
  to hold that whole adjacency graph in its head and lay out geometry that
  satisfies it, not just place ten biomes wherever they fit.
- **Ecological causality**: water has to behave like water. Mountain melt
  feeds a wet corridor through the forest, highlands, jungle, and grassland,
  then widens into a coastal delta. Desert is a rain-shadow basin with no
  through-river. The volcano sits outside that whole system, and lava
  touching water is supposed to turn into obsidian. None of this is
  decorative; it's a small causal system the model has to simulate
  correctly, not just describe.
- **Elevation and scale reasoning**: peaks dominate, shelves sit mid-height,
  plains stay low, and cliffs drop sharply, and every biome still has to
  read as its own region from a high orbit instead of collapsing into its
  neighbor.
- **Ecological grounding for flora and fauna**: cacti belong in the desert,
  pines in the snow forest, deer at jungle edges and across the grassland.
  Placing life that actually matches its climate is a grounding task, not
  decoration.
- **Temporal / systems reasoning**: a day/night cycle, a seasonal cycle,
  and cyclic weather (rain, snow, blizzard, sandstorm, ash) that has to stay
  staggered by biome instead of blanketing the whole island at once.
- **UI and interaction logic**: a clickable biome legend that flies the
  camera to each region, plus a live season readout, testing whether the
  model can wire 3D scene state to on-screen UI, not just render geometry.
- **Constrained code generation**: everything ships as one self-contained
  HTML file, no build step, no separate assets, CDN Three.js only. It has
  to just open in a browser and run.

There's no single correct island, so nothing is scored against a template.
Each test checks whether a property of the description holds in the world
the model built, however it chose to build it.

## How it's judged

Every world goes through the same five tests, 280 points in total. The
maximums are fixed, so totals compare directly across models.

- **Voxel island** (40): is it the thing that was asked for? A cube-built
  island floating in a void, water resting on solid ground, and no visible
  rendering bugs.
- **Coverage and placement** (20): is every biome built, and does each sit
  next to the right neighbours at the right height?
- **Micro-contents** (100): does each biome contain what makes it that
  biome? Cacti on the desert flats, mangroves in the swamp, a glowing crater
  on the volcano.
- **Physics** (100): do things look right and move the right way? Rain
  falls, rivers flow, clouds drift, lava glows.
- **Temporal cycles** (20): do the day/night cycle and the seasons actually
  change the world, rather than only a label on screen?

Each world runs in a headless browser with its randomness seeded, so every
run builds the same island, and its clock is pinned so time of day and
season can be set on demand. From there, several judges work on the same
evidence:

- **LLM as a judge, over the code.** A language model reads the source and
  has to quote the exact lines that build each item. Every quote is checked
  word for word against the file, so a judge can't award points for code
  that isn't there.
- **VLM as a judge, over the frames.** A vision model looks at captured
  views of the running world: fixed camera angles, four times of day, four
  seasons, and close-ups of every biome. A blind pass first confirms each
  close-up really shows the biome it claims to.
- **Agents as judges.** A browser agent uses the world's own legend and
  camera to frame each biome, and when the frames show something the code
  check missed, a code-search agent goes back through a read-only copy of
  the source to settle it.
- **Measured, not asked.** Motion, day/night brightness and seasonal colour
  are measured from the pixels themselves. "It moves" only counts if
  consecutive frames actually differ.

Most items are judged twice, once from the code and once from the running
world, because each catches the other's mistakes: code can read right and
render wrong, and a screenshot can be framed on the wrong region. Every
verdict, quote and frame is kept alongside the score, so any result can be
traced back to its evidence.

The hand-tuned reference island isn't part of the grading. It's there for
people: a picture of what the prompt is reaching for, to compare the
generated worlds against by eye.

## The placement graph

This is the prompt's ecology drawn as a graph instead of prose. A biome
isn't defined by any single relation, so the edges are typed: the solid
teal spine is the one required water corridor — mountain melt feeds the
conifer forest, then the highlands, then the jungle, then the grassland
plateau, then out to the coastal delta.

The other edges show the relations that aren't that perennial line, each
drawn differently on purpose. The flowering grove has two valid sources
rather than one — down the highland slope, and/or across from the plains —
the dashed teal "and/or" edges, which give the graph its one real cycle
(two paths reach the grove). The dotted gold edge to the desert is the
subtle one: the desert isn't cut off from nothing, it's linked to the
plains only by dry washes that fade out before they arrive — a genuine
relation, but never a through-river. The dotted amber edge into the
volcano marks the single causal rule that still reaches it: lava touching
water quenches to obsidian.

Desert and volcano stay dashed boxes because both are off the perennial
water system, and the model has to preserve that — reading the desert's
faint dry-wash link without ever routing a real river through it, and
leaving the volcano to lava alone.

## Try it yourself

You don't need this site to run the benchmark, just the prompt and a
model.

1. Open the prompt below and copy it.
2. Paste it into any model chat: `Claude`, `ChatGPT`, `Gemini`, whatever
   you want to try.
3. Save the raw output, with no surrounding text, as `world.html`.
4. Open that file in your browser and look around.
